# V1 reconciliation, 10 October 2026

The simplified application at `030cbdd` is the accepted personal-use v1 baseline.
This reconciliation changes its release contract and evidence organization, not
its reasoning rules. [Scenario-local tags](../reason-commons-spec/README.md) own
scope; [the manifest](../reason-commons-spec/delivery-phases.json) declares the
progression and runners. [Editorial decisions](../reason-commons-spec/reconciliation-decisions.json)
record dispositions, including previous scope. [The delivery report](v1-delivery.md)
records checks actually run. All original S01–S150 identities are preserved.

RC helps people find useful next actions with less analysis and record keeping.
People provide values, observations and real-world knowledge. AI can help identify
relevance and constraints, while its own cost, human attention and accumulated
reasoning are assessed too. More records do not establish more progress. A complete
tree, measurement, trial, or decision questionnaire is not a prerequisite to
continue an imported conversation.

## Meaning and provenance

The development story is explicitly hypothetical/editorial. The demon is a
metaphor for lost MVP discipline. Git establishes code changes, not the truth of
that reconstruction, its causes or anyone's agreement. The real imported history
records retained source bytes, AI interpretations and actual local adoption as
separate events. Adoption makes a reconstruction usable in this commons; it does
not authenticate it or turn an interpretation into a participant's statement.

The RC-on-RC import is the primary editable continuation example. Its adopted
state has 119 accepted reconstructed proposals, source attachments, ten
revisions, an ordinary response draft and no recorded trials. The Next step lets
the participant correct or extend that prior work. The earlier proposal to start
by asking the user to name the most important decision or choose a test is
superseded. [Working import](restoration/working-import.md) explains the real
artifact and its original provenance. Native `.reasoncase` archives and source
files remain unchanged, including the separate consent-draft Second Renaissance
reading example. The guided practice tour is a deliberately literal offline loop;
its fictional successful result does not establish a real participant outcome.

## A coherent development progression

This is a dependency argument culminating in the app, not a claim about actual
historic releases or a mandatory sequence for participants.

| Increment | What it adds | Dependency / release |
|---|---|---|
| p0 | Durable, attributed input and atomic reasoning commits; inspect, retry, resume and export | Foundation; v1 |
| p1 | Proposals, dependency-aware membership, rejection, undo and acceptance policy | p0; v1 |
| p2 | Inspectable tree statements and links, sources, history and exact versions | p1; v1 |
| p3 | Guided loop, editable work, revisions, reviews and terminal presentation | p2; v1 |
| p4 | Prior-work import and continuation, home/setup, providers, personal settings, costs and examples | p3; accepted v1 exit |
| p5 | Formal causal views, graph explanations, branching trials and richer implementation reasoning | p4; future |
| p6 | Structured group positions, reliance, facilitated conflict and resolution | p5; future |
| p7 | Full question/canvas focus, richer reasoning and implementation tools | p6; future |

Delivery increments are distinct from the compatible serialized
`delivery_profile: "p2"`. Future authored envelopes/illustrations also retain
legacy profiles. There is no schema migration implied by retagging.
